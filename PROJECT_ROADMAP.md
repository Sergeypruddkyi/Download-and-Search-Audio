# PROJECT_ROADMAP — Download and Search Audio

## Главная цель и ожидаемый результат

Портативное Windows-приложение **Download and Search Audio**: загрузка аудио с YouTube
(только аудио, Best available, без выбора качества пользователем), поиск музыкальных
файлов в выбранной папке и подпапках, предупреждение о возможных дубликатах перед
загрузкой и Audio Trimmer. Тёмная тема, зелёные акценты, английский интерфейс,
эталон внешнего вида — `Assets\front view panel app.png`.

Итог: portable-сборка в `dist` (self-contained single-file EXE .NET 10 + sidecar
инструменты), запускаемая без установки .NET Runtime.

## Результаты аудита источников (выполнено 2026-10-25)

### YouTubeDownloader-Net10 (WinForms .NET 10) — переиспользуем

- `src\DarkTitleBar.cs` — весь кастомный хром окна: `ChromeApi` (P/Invoke),
  `ChromePanel`, `DarkTitleBar` (WM_NCCALCSIZE/WM_NCHITTEST/WM_GETMINMAXINFO/
  WM_DPICHANGED, кнопки Min/Max/Close на Segoe MDL2 Assets). Скопировано и адаптировано.
- `Theme` (MainForm.cs:15–58) — палитра тёмной темы; адаптирована под зелёные акценты макета.
- `src\Settings.cs` — атомарный INI рядом с EXE (write .tmp → File.Replace → .bak);
  скопировано, ключи адаптированы.
- `src\AppPaths.cs` — портативная схема sidecar-путей (yt.exe/ffmpeg.exe/ffprobe.exe
  рядом с EXE); адаптировано (упрощено на этапе каркаса, расширится на этапе загрузчика).
- `src\YouTubeUrl.cs`, `YtDlpRunner.cs` (BuildStartInfo/DownloadArgs/OutputParser/
  KillTree), `VideoDownloadEngine.cs`, `YtDlpDownloadEngine.cs`, `MediaProbe.cs`,
  `ErrorClassifier.cs` — взять на этапе 2 (загрузчик).
- Бинарники: `E:\Projects\YouTubeDownloader-Net10\dist\YouTubeDownloader\{yt.exe,
  deno.exe, ffmpeg.exe, ffprobe.exe}` — копировать в `dist` нового приложения на
  этапе 2 (не скачивать повторно).
- `app.manifest` (asInvoker, PerMonitorV2) — скопировано с заменой имени.
- Отличие от макета: в источнике нет скруглённых углов окна и карточек — добавлено
  самостоятельно (DWMWA_WINDOW_CORNER_PREFERENCE для окна, GraphicsPath-регионы для карточек).

### ComfyImageViewer (WPF .NET 10) — переиспользуем паттерн, не код

- Стек WPF/MVVM не совпадает с WinForms-каркасом — сам код UI не переносится.
- Переиспользуем паттерн рекурсивного поиска (ModelFamilySearchService.FindAsync,
  ~40 строк): `Directory.EnumerateFiles(root, "*", new EnumerationOptions {
  RecurseSubdirectories = true, IgnoreInaccessible = true, AttributesToSkip =
  FileAttributes.ReparsePoint })` + long-path (`\\?\` от порога 240 симв.) + отмена
  через CancellationToken на каждом файле + потоковая выдача результатов.
- `ScanPaths.TryCreateEntry` — отказоустойчивое чтение FileInfo (size) с проглатыванием
  IOException/UnauthorizedAccessException — взять как образец.
- Фильтра по имени файла в источнике нет — реализовать самостоятельно
  (Contains, OrdinalIgnoreCase). Индексации в источнике нет и в новом проекте не
  планируется (поиск — свежий обход дерева, см. решение ниже).

### Принятые архитектурные решения

1. Стек: **WinForms .NET 10, code-first UI** (как YouTubeDownloader) — максимум
   прямого переиспользования хрома/темы/механики, одна плоская папка `src`.
2. Публикация: self-contained single-file win-x64 в `dist\DownloadSearchAudio\`
   (параметры как у источника); sidecar-инструменты — рядом с EXE, НЕ в бандле.
3. Поиск: без БД и индекса — свежий рекурсивный обход по запросу пользователя
   (коллекции пользователей умеренного размера; индекс усложнит сборку без
   обоснованной выгоды). Пересматривается, если поиск окажется медленным.
4. Дубликаты: сравнение по названию из YouTube против имён файлов коллекции;
   длительность/размер — дополнительными признаками через ffprobe (этап 4).
5. Триммер: FFmpeg из уже имеющихся sidecar-инструментов, без новых зависимостей.
6. Иконки UI: глифы Segoe MDL2 Assets (как в источнике), без новых ресурсов.

  `UiGraphics.RoundedRect` не проверял эти граничные случаи и передавал
  некорректные прямоугольники в `GraphicsPath.AddArc`, что вызывало исключение GDI+.

  **Исправления в `src\UI.cs`**:
  1. `UiGraphics.RoundedRect(Rectangle, int)` — добавлена ранняя проверка
     `if (r.Width <= 0 || r.Height <= 0) return p;` (пустой путь).
  2. `Card.UpdateRegion()` — пропуск создания региона при `Width <= 0 || Height <= 0`.
  3. `InputBox.OnResize()` — пропуск создания региона при некорректных размерах.
  4. `ComboPopup.OnResize()` — пропуск создания региона при некорректных размерах.
  5. Все `OnPaint` методы (Card, InputBox, AudioTransportButton, IconChip,
     RoundedButton, ProgressLite, DarkCombo, SearchResultsViewport.scrollbar) —
     добавлена ранняя проверка `if (Width <= 1 || Height <= 1) return;` (или
     аналогичная) перед построением геометрии.
